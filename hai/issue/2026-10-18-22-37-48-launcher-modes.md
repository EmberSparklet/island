## 背景

方案 `hai/reference/extensions/README.md` §5 的 P3b 之后新增的一段（规划稿见 `hai/reference/extensions/launcher-modes.md`，用户原话拆解为 R4-1…R4-7）。

现状（P3a + P3b，`53705bb`）：键盘模式下 `⇥` 只有两个硬编码状态 —— 筛选任务 / 提问，目标清单只能靠 `ISLAND_LAUNCHER_TARGETS` 环境变量配，提问永远是"只预填、不自动发送"。

用户要的是：**模式清单在设置页里配**，一行一个模式，第一行是默认模式，拖拽排序；每个模式可带**有开关、有自定义标签**的附加参数（`autosend=1` 只是第一个例子）；内置的 DeepSeek 也能加自定义选项。

## 范围

- `IslandCore`（纯逻辑，TDD，100% 覆盖）：
  - `LauncherOption {key, value, label, isEnabled}`；`LauncherTarget` 增加 `options`；新增 `LauncherMode {searchTasks, target(LauncherTarget)}` 与有序模式环。
  - `Launcher.url(for:query:)` 追加**已启用**的附加参数；空问题仍只开基址。
  - `nextModeIndex(from:count:)` 取代 `composeTabAction`（环回绕；`searchTasks` 恒在环里恰一次，可拖、不可删）。
  - `UserDefaultsLauncherStore`（JSON + schema 版本 + 坏数据回落）；`LauncherSettings.resolve(environment:stored:)` 优先级：`ISLAND_LAUNCHER=off` > 设置页 > `ISLAND_LAUNCHER_TARGETS` > 内置。
  - 设置页需要的纯函数：增 / 删 / 改 / 移动、id slug + 去重、字段校验。
- 设置页（AppKit，新文件 `Sources/Island/LauncherSettingsView.swift`，登记进 `coverage.config`）：`HotkeySettingsWindow` 新增 tab；`NSTableView` 拖拽排序；行内选项勾选框；新增 / 编辑 sheet；校验失败就地标红、拒绝保存。
- 悬浮窗：模式环渲染（胶囊 + 占位符 + footer），`⇥` 换模式、`↩` 提交、`esc` 回 `搜索任务`（已在筛选态则收起）。
- 文档：`hai/CONTEXT.md`、`hai/reference/extensions/README.md`（P3c 落地说明 + 决策 D14）、`README.md` / `README.zh-CN.md`（仅当涉及用户可见用法）。

不做（写清以免默认扩张）：

- 插件 manifest 的 `targets` 字段与 `plugin.json` 解析（README §4.4 遗留，另开 issue）。
- 剪贴板兜底动作、AX / CGEvent 注入按键、每模式全局快捷键（R3 / P4）。
- 按站点名特判（不写"只有 deepseek 才能 autosend"这类分支）。
- 引入配置文件：用户偏好只进 `UserDefaults`（README §4.8 的划线）。

## 期望结果

- 设置页可拖拽排序模式；第一行即热键召唤后直接进入的模式；`搜索任务` 行可拖不可删。
- 每个网页模式可勾选附加参数（如「自动发送」），`--print-config` 与悬浮窗 footer 反映当前配置。
- 环 = `[搜索任务, DeepSeek]`、不勾自动发送时，行为与 `53705bb` 逐条等价（回归）。
- `make verify` 全绿（覆盖率不低于 100 基线）。

## Decision

2026-10-18 用户在本机会话中回答开工前的四个问题，逐条记录授权范围：

1. **实测（Q0）：`https://chat.deepseek.com/?q=测试&autosend=1` 可以自动触发问答**（用户原话）。据此确认 DeepSeek 的预填与自动发送端到端可用，§7 的"运行时未验证"一项从"未验证"转为"已由用户实测"。授权范围：以用户这次实测为准，不再要求复现。
2. **环的语义（Q1）：是**（选"第一行 = 热键召唤后直接进入的模式"）。`搜索任务` 恒在环里、可拖不可删，`esc` 的取消去处因此恒定。
3. **内置清单（Q2）：只内置"已知能支持"的部分**。DeepSeek 已实测支持 → 内置，并预置一个**默认不勾**的 `autosend=1` 选项（标签「自动发送」）。Kimi **不内置**：本轮实测 `kimi.moonshot.cn/_prefill_chat?...` 只 302 到 `www.kimi.com/_prefill_chat?...`，而当前 `kimi-web-seo` bundle 里该路由是 `{path:'/_prefill_chat', redirect:'home'}`（参数被丢弃），`send_immediately` **0 命中** —— 旧域名的能力在新域名已不存在。Codex 无 URL 目标（本机无图形客户端）。两者都走"用户自定义"。
4. **范围（Q3）：一次落地**（选"一个 issue 做完"），不拆两个 issue。

此外，用户此前明确"先不发版"，本轮不跑 `./scripts/publish.sh`。
